# AI Critique — HW04 Automation Testing

The AI's most significant failure this assignment was subtle rather than obvious: the destructive account-deletion tests for FR-19 were restricted to a single browser to avoid corrupting shared database state, but the AI chose Chromium — the *first*-declared project in Playwright's config — without realizing Playwright executes whole projects sequentially in declaration order. Chromium's pass deleted the seed accounts before Firefox and WebKit had even started, and every dependent test in those two browsers then silently *passed* instead of failing — not because the underlying critical bug was fixed, but because a broken login coincidentally produced the same on-screen state a correct rejection would have. This is a genuinely dangerous class of AI mistake: it produced a suite that looked healthy while actually failing to test what it claimed to test.

The AI failed to catch this because it required reasoning about the *interaction* between two separate systems' semantics — Playwright's own scheduling order and the SUT's irreversible mutation — neither of which is visible from reading either system in isolation. It was only caught by noticing that results for a server-side-only bug varied across browsers, which should never happen, and treating that inconsistency as a hard signal rather than dismissing it.

The principle I've taken from this: never trust that a "safe-looking" test isolation choice (like restricting to one browser) is actually safe without empirically verifying the assumption it depends on — in this case, execution order. AI-generated tests need to be judged not just by whether they pass, but by whether a pass would actually mean what it claims to mean.
